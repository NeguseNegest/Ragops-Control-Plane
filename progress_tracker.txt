Implemented files

Implemented chunking module
- Added ChunkConfig with defaults:
  - DEFAULT_CHUNK_SIZE = 250
  - DEFAULT_CHUNK_OVERLAP = 50
  - default strategy = heading
- Added strategy normalization so aliases such as fixed, fixed_size, overlap, overlapping, with_overlap, heading, headings, and heading_aware map to stable strategy names.
- Added validation that chunk_overlap must be smaller than chunk_size.
- Added whitespace-token span extraction with a regex instead of a tokenizer dependency.
- Preserved original text spacing inside chunks by slicing from character offsets rather than rebuilding text from token lists.
- Added fixed-size chunking:
  - split_fixed_size(...)
  - no overlap by default
  - emits stable token windows
- Added overlapping chunking:
  - split_with_overlap(...)
  - uses chunk_size minus chunk_overlap as the window step
  - reuses trailing tokens in the next chunk
- Added heading-aware chunking:
  - split_by_headings(...)
  - detects Markdown headings with # through ######
  - strips heading anchors like { #intro } from heading metadata
  - splits documents into heading sections first
  - applies token windows inside long sections
  - includes heading, heading_level, and section_index metadata when available
- Added chunk metadata:
  - chunk_index
  - chunking_strategy
  - chunk_size
  - chunk_overlap
  - chunk_start_token
  - chunk_end_token
  - chunk_start_char
  - chunk_end_char
  - section_index where available
  - heading and heading_level where available
- Added deterministic chunk hashes:
  - build_chunk_hash(text)
  - SHA256 over the exact chunk text
- Added deterministic chunk IDs:
  - build_chunk_id(document_id, strategy, chunk_index, chunk_hash)
  - UUID5 namespace based on ragops-control-plane/chunks/v1
  - ID inputs include source document ID, chunking strategy, chunk index, and chunk hash
- Added chunk_document(...) for one document.
- Added chunk_documents(...) to yield chunks across documents in input order.

Day 12: End-to-end RAG path
Goal from ProjectPlan.tex
- Make the first complete RAG request work.
- Connect POST /query to dense retrieval.
- Send retrieved context to the generation module.
- Return the answer, citations, chunks, and latency.
- Add basic error handling.
- Acceptance criterion: POST /query returns a grounded answer.

Implemented request flow
- A client sends JSON containing query and top_k to POST /query.
- FastAPI parses and validates that JSON as QueryRequest.
- The endpoint starts a high-resolution request timer.
- retrieve_chunks(...) opens a Qdrant client connected to http://localhost:6333.
- retrieve_dense(...) validates and cleans the query.
- The query is embedded with sentence-transformers/all-MiniLM-L6-v2, matching the model used for indexed chunks.
- Qdrant searches the rag_chunks collection with cosine-based vector similarity.
- Search results are converted into ranked RetrievedChunk objects with text, scores, metadata, and source paths.
- The Qdrant client is closed after retrieval, including when retrieval raises an exception.
- generate_answer(...) receives the original query and retrieved chunks.
- The Day 9 citation module creates and deduplicates numbered citations such as [1].
- The generation module builds citation-labeled context and a prompt that requires context-only answers, citations, and "I do not know" behavior for unsupported questions.
- LocalTemplateGenerationClient supplies the current deterministic answer implementation.
- The endpoint converts internal chunks and citations into API response schemas.
- QueryResponse returns answer, citations, citation_text, chunks, used_chunk_ids, and total latency_ms.

Implemented error handling
- ValueError is converted into HTTP 400 with the validation message, for example when the query is empty.
- Unexpected retrieval errors on POST /retrieve are converted into HTTP 503 with "Unable to retrieve chunks."
- Unexpected retrieval or generation errors on POST /query are converted into HTTP 503 with "Unable to generate answer."
- Exceptions are chained with "from error" so the original cause remains available for debugging.
